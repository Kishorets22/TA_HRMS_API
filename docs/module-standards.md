# Module Standards

These rules apply to every feature module in `src/modules`. The **Holiday module** (`src/modules/masters/holidays`) is the reference implementation: when in doubt, copy how it does it.

Modules already following these standards: Holidays, Departments, Employment Types, Organizations, Branches.

---

## 1. Folder structure

```
src/modules/masters/holidays/
├── holiday.module.ts
├── holiday.controller.ts
├── holiday.service.ts
├── constants/
│   └── holiday.constants.ts          # HOLIDAY_RESPONSES (+ limits, if any)
├── dto/
│   ├── create-holiday.dto.ts
│   ├── update-holiday.dto.ts
│   ├── holiday-query.dto.ts          # extends PaginationQueryDto
│   └── holiday-response.dto.ts       # response class + response types
├── entities/
│   └── holiday.entity.ts
├── repositories/
│   └── holiday.repository.ts
└── utils/
    └── holiday-validation.utils.ts   # isValidHolidayId, isValidHolidayDate
```

- One constants file per module. No separate `*-response.constants.ts`.
- DTOs sit directly in `dto/`. No `dto/requests` or `dto/responses` subfolders.
- One concrete repository class. No abstract repository + `Impl` pair.
- Register the module directly in `src/app.module.ts`. Don't wrap modules in a grouping module such as `MastersModule`.

## 2. Naming

### Function names: identical in every layer

The controller, service and repository use the **same name** for the same operation:

| Operation | Controller | Service | Repository |
|---|---|---|---|
| Create | `createHoliday` | `createHoliday` | `createHoliday` |
| List | `getAllHoliday` | `getAllHoliday` | `getAllHoliday` |
| Get one | `getHolidayById` | `getHolidayById` | `getHolidayById` |
| Update | `updateHoliday` | `updateHoliday` | `updateHoliday` |
| Delete | `deleteHoliday` | `deleteHoliday` | `deleteHoliday` |

Don't use `creatingHoliday`, `retrievingAllHolidays`, `findAll`, `findById`, `removeX` or `xById` suffixes.

Repository helpers that have no controller equivalent use these names:

| Helper | Purpose |
|---|---|
| `holidayExists(id)` | `true` / `false`; call before `getHolidayById` |
| `isDuplicateHoliday(..., excludeId?)` | duplicate check for create and update |

### Variable names: full DTO names

```ts
// ✅
async createHoliday(createHolidayDto: CreateHolidayDto)
async updateHoliday(id: number, updateHolidayDto: UpdateHolidayDto)
async getAllHoliday(holidayQueryDto: HolidayQueryDto)

// ❌
async createHoliday(dto: CreateHolidayDto)
async getAllHoliday(query: HolidayQueryDto)
async createHoliday(data: CreateHolidayDto)
```

## 3. Types: banned keywords

Don't use these in module code:

| Banned | Use instead |
|---|---|
| `any` | a real type |
| `unknown` | a real type; for caught errors use `(error as Error)` |
| `undefined` (e.g. `x !== undefined`) | a truthy check `if (x)` or `x ?? fallback` |
| `\| null` (e.g. `Promise<Holiday \| null>`) | optional fields `field?: string`; see the repository rules for lookups |
| `PartialType`, `OmitType`, `PickType` | write the DTO out in full |
| definite assignment `field!: string` | `field: string` (`strictPropertyInitialization` is off) |

## 4. Entity

**The database schema source of truth is `.test/hrms_resolved.sql`.** Entities must mirror it exactly. Never edit the SQL file to fit the code.

- **Names:** table, column and constraint names are copied from the SQL file.
- **IDs:** use `bigint` in the database, typed as `number` in TypeScript. The pg driver is set up in `src/database/typeorm.config.ts` to return `bigint` as a number. Primary keys use `GENERATED BY DEFAULT AS IDENTITY`:

  ```ts
  @PrimaryGeneratedColumn('identity', {
    name: 'holiday_id',
    type: 'bigint',
    generatedIdentity: 'BY DEFAULT',
  })
  id: number;

  @Column({ name: 'company_id', type: 'bigint' })
  companyId: number;
  ```

- **Foreign keys:** use the SQL file's constraint name and `ON DELETE NO ACTION`, which is the SQL default:

  ```ts
  @ManyToOne(() => Company, { nullable: false, onDelete: 'NO ACTION' })
  @JoinColumn({
    name: 'company_id',
    referencedColumnName: 'id',
    foreignKeyConstraintName: 'fk_holidays_company_id_company_company_id',
  })
  company: Company;
  ```

- **Unique rules:** use the SQL file's names. An inline `UNIQUE` column is named `<table>_<column>_key` by Postgres; use `@Unique('<that name>', [...])`. A `CREATE UNIQUE INDEX` in the SQL file becomes `@Index('<name>', [...], { unique: true })`.
- **No extra constraints or indexes** that the SQL file doesn't define.
- **Nullable columns** are optional properties: `holidayType?: string`.

## 5. DTOs

### Create DTO
- **Every field has validation decorators and Swagger docs.**
- **Text input:** trim it with a shared `trim` transform, exported from the create DTO:

  ```ts
  export const trim = ({ value }: TransformFnParams): string =>
    typeof value === 'string' ? value.trim() : value;

  @Transform(trim)
  @IsString()
  @IsNotEmpty()
  @MaxLength(150)
  holidayName: string;
  ```

- **ID fields** are positive integers:

  ```ts
  @Type(() => Number)
  @IsInt({ message: 'Company ID must be a positive number' })
  @Min(1, { message: 'Company ID must be a positive number' })
  companyId: number;
  ```

### Update DTO
- **Written out in full**, with every field `@IsOptional()`. No `PartialType` or `OmitType`.
- **Leave out fields that can't change**, such as `companyId`. The global `ValidationPipe` (`forbidNonWhitelisted`) then rejects them with a 400.

### Query DTO
- **Extends `PaginationQueryDto`** (`page`, `limit` up to 100, `search`), then adds filters such as `companyId`, `fromDate` and `toDate`.

### Response DTO
- **One class for the data**, plus type aliases for the response shapes:

  ```ts
  // Error responses omit `data`.
  export type HolidayResponse = GenericResponseDto<HolidayResponseDto>;
  export type HolidayListResponse = GenericListResponseDto<HolidayResponseDto>;
  ```

## 6. Response constants

All responses come from one `HOLIDAY_RESPONSES` object in `constants/holiday.constants.ts`. Keys are camelCase.

```ts
export const HOLIDAY_RESPONSES = {
  created:  (data) => ({ success: true,  message: `Holiday ${data.holidayName} created successfully`, statusCode: HttpStatus.CREATED, data }),
  listed:   (data, total) => ({ ..., statusCode: HttpStatus.OK, data, total }),
  fetched:  (data) => ({ ..., statusCode: HttpStatus.OK, data }),
  updated:  (data) => ({ ..., statusCode: HttpStatus.OK, data }),
  deleted:  (id)   => ({ ..., statusCode: HttpStatus.OK, data: { id } }),

  notFound:         (id)  => ({ success: false, message: `Holiday with ID ${id} not found`, statusCode: HttpStatus.NOT_FOUND }),
  invalidId:        (id)  => ({ success: false, message: `Invalid holiday ID: ${id}`,       statusCode: HttpStatus.BAD_REQUEST }),
  duplicate:        ()    => ({ success: false, message: 'Holiday already exists for this company', statusCode: HttpStatus.CONFLICT }),
  companyNotFound:  (cid) => ({ ..., statusCode: HttpStatus.NOT_FOUND }),
};
```

- **Status codes:** always use `HttpStatus.*`, never raw numbers.
- **Error responses:** have **no `data` key**. Never send `data: null`.

## 7. Validation utils

ID and value checks return a boolean. They don't throw.

```ts
export function isValidHolidayId(id: number): boolean {
  return Number.isSafeInteger(id) && id > 0;
}
```

## 8. Repository

```ts
@Injectable()
export class HolidayRepository {
  constructor(
    @InjectRepository(Holiday)
    private readonly repository: Repository<Holiday>,
  ) {}

  async createHoliday(createHolidayDto: CreateHolidayDto): Promise<Holiday> {
    const holiday = this.repository.create(createHolidayDto);
    return this.repository.save(holiday);
  }

  async updateHoliday(holiday: Holiday): Promise<Holiday> {
    return this.repository.save(holiday);
  }

  holidayExists(id: number): Promise<boolean> {
    return this.repository.existsBy({ id });
  }

  // Call holidayExists first; throws when not found.
  getHolidayById(id: number): Promise<Holiday> {
    return this.repository.findOneByOrFail({ id });
  }

  // Case-insensitive; pass excludeId on update so the record doesn't match itself.
  async isDuplicateHoliday(companyId: number, holidayDate: string, holidayName: string, excludeId?: number): Promise<boolean> { ... }

  async getAllHoliday(holidayQueryDto: HolidayQueryDto): Promise<{ data: Holiday[]; total: number }> { ... }

  async deleteHoliday(id: number): Promise<boolean> {
    const result = await this.repository.delete(id);
    return Boolean(result.affected);
  }
}
```

- **Create** builds and saves in one call.
- **Lookups don't return `null`.** Check `holidayExists` first, then `getHolidayById` (`findOneByOrFail`).
- **Duplicate checks** are **case-insensitive** (`LOWER(...) = LOWER(...)`) and take an optional `excludeId`.
- **List queries** use parameterised SQL (`:param`) and never build SQL from user input.
- **Soft-delete modules** (Organizations, Employment Types) update a status flag in `deleteX` instead of deleting the row, and still return `boolean`.

## 9. Service

### Return in `try`, throw only in `catch`

Expected failures (400 / 404 / 409) are **returned** as response objects. The only `throw`s are in the `catch` block.

```ts
async updateHoliday(id: number, updateHolidayDto: UpdateHolidayDto): Promise<HolidayResponse> {
  try {
    if (!isValidHolidayId(id)) {
      return HOLIDAY_RESPONSES.invalidId(id);
    }

    const exists = await this.holidayRepository.holidayExists(id);
    if (!exists) {
      this.logger.warn(`[HOLIDAY] Holiday ${id} not found`);
      return HOLIDAY_RESPONSES.notFound(id);
    }

    const holiday = await this.holidayRepository.getHolidayById(id);

    const holidayName = updateHolidayDto.holidayName ?? holiday.holidayName;
    const holidayDate = updateHolidayDto.holidayDate ?? holiday.holidayDate;

    const duplicate = await this.holidayRepository.isDuplicateHoliday(
      holiday.companyId, holidayDate, holidayName, holiday.id,
    );
    if (duplicate) {
      return HOLIDAY_RESPONSES.duplicate();
    }

    // Assign only the editable fields, never the raw request body.
    holiday.holidayName = holidayName;
    holiday.holidayDate = holidayDate;
    holiday.holidayType = updateHolidayDto.holidayType ?? holiday.holidayType;

    const updated = await this.holidayRepository.updateHoliday(holiday);

    return HOLIDAY_RESPONSES.updated(updated);
  } catch (error) {
    if (error instanceof HttpException) {
      throw error;
    }

    this.logger.error(
      `[HOLIDAY] An error occurred while updating the Holiday: ${(error as Error).message}`,
      (error as Error).stack,
    );

    throw new HttpException(
      'An error occurred while updating the Holiday',
      HttpStatus.INTERNAL_SERVER_ERROR,
    );
  }
}
```

### Rules
- **Catch block:** use the format above in every method. Only the message changes per function:

  | Function | Message |
  |---|---|
  | create | `An error occurred while creating the Holiday` |
  | getAll | `An error occurred while retrieving all Holidays` |
  | getById | `An error occurred while retrieving the Holiday` |
  | update | `An error occurred while updating the Holiday` |
  | delete | `An error occurred while deleting the Holiday` |

- **Log before throwing a 500**, with the real cause and stack. The client only sees the clean message.
- **Never `Object.assign(entity, dto)`.** Assign each editable field explicitly with `dto.field ?? entity.field`.
- **Check that parent records exist before creating**, e.g. the company for a holiday, and return `companyNotFound`.
- **No helper wrappers** such as `handleError`, `toHttpException` or `logSeparator`.
- **Logging:** use a `[HOLIDAY]` prefix. `log` for normal steps, `warn` for expected failures, `error` for 500s.

## 10. Controller

```ts
// TODO(auth): add AuthGuard and company-level authorization once auth exists.
@ApiTags('Holidays')
@Controller('v1')
export class HolidayController {
  private readonly logger = new Logger(HolidayController.name);

  constructor(private readonly holidayService: HolidayService) {}

  @Patch('holiday/:id')
  @ApiOperation({ summary: 'Update holiday by ID' })
  @ApiParam({ name: 'id', example: '9' })
  async updateHoliday(
    @Param('id', ParseIntPipe) id: number,
    @Body() updateHolidayDto: UpdateHolidayDto,
    @Res({ passthrough: true }) res: Response,
  ): Promise<HolidayResponse> {
    try {
      const response = await this.holidayService.updateHoliday(id, updateHolidayDto);

      res.status(response.statusCode);

      return response;
    } catch (error) {
      // same catch block as the service, same message
    }
  }
}
```

- **Routes:** `@Controller('v1')`, with singular paths for one record and plural for the list:

  | Method | Path |
  |---|---|
  | `POST` | `/v1/holiday` |
  | `GET` | `/v1/holidays` |
  | `GET` | `/v1/holiday/:id` |
  | `PATCH` | `/v1/holiday/:id` |
  | `DELETE` | `/v1/holiday/:id` (with `@HttpCode(HttpStatus.OK)`) |

- **Always set `res.status(response.statusCode)`.** Returned errors would otherwise go out as HTTP 200.
- **Use the same try/catch block as the service.**
- **Route IDs** are `number`, parsed with `ParseIntPipe`, which returns 400 for non-numeric input. The service also checks for a positive ID (`isValidHolidayId`) and returns `invalidId` for `0` or negative values.

## 11. App-wide settings these standards rely on

`src/main.ts` registers a global validation pipe:

```ts
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,             // strip unknown fields
    forbidNonWhitelisted: true,  // ...and reject the request with 400
    transform: true,             // run @Type / @Transform, apply DTO defaults
  }),
);
```

Without it, no DTO decorator runs.

## 12. Checklist for a new or refactored module

- [ ] Folder structure matches section 1. The module is registered in `app.module.ts`.
- [ ] Entity mirrors `.test/hrms_resolved.sql`: names, `bigint` columns typed `number`, FK and unique constraint names, `NO ACTION`.
- [ ] Same function names in the controller, service and repository.
- [ ] Full DTO variable names (`createXDto`, `updateXDto`, `xQueryDto`).
- [ ] No `any`, `unknown`, `undefined`, `| null`, `PartialType`, `OmitType` or `!`.
- [ ] The update DTO is written out in full. Fields that can't change are left out.
- [ ] Text fields are trimmed. ID fields are `number`, validated with `@Type(() => Number)`, `@IsInt()` and `@Min(1)`. Route IDs use `ParseIntPipe`.
- [ ] The repository has `xExists` + `getXById` (`findOneByOrFail`) and `isDuplicateX(..., excludeId?)`.
- [ ] The service returns responses in `try` and throws only in `catch`, with a per-function message and `logger.error`.
- [ ] The update assigns only editable fields.
- [ ] The controller uses `@Controller('v1')`, singular and plural routes, `res.status(response.statusCode)`, and the same catch block.
- [ ] Error responses have no `data` key.
